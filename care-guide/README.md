# 병원 길잡이 (시험판)

어르신이 휴대폰에 **말로** 물어보면

- 증상에 맞는 **진료과**를 알려 드리고
- **지금 문 연** 가까운 병원·약국·응급실을 찾아 전화·길찾기 버튼과 함께 보여 주고
- **큰 병원(상급종합병원) 갈 때**, **보험금 청구할 때** 챙길 서류를 체크리스트로 정리해 주고
- **건강수첩**에 넣어 둔 건강검진 결과·지병·드시는 약을 기억해 두었다가 안내할 때 참고하는

웹앱(PWA)입니다. 자판으로 써도 되고, 답은 소리로 읽어 드립니다.

## 바로 실행해 보기

```bash
cd care-guide
npm install
npm start          # http://localhost:3000
npm test           # 진료시간 계산·증상 분류·응답 파싱 테스트
```

키가 하나도 없어도 돌아갑니다.

| 키 | 없을 때 | 있을 때 |
|---|---|---|
| `EGEN_SERVICE_KEY` | 예시 병원/약국 데이터("(예시)"가 붙은 가짜 기관) | 국립중앙의료원 실데이터 |
| `ANTHROPIC_API_KEY` | 규칙 기반 기본 안내(키워드로 진료과·서류 판단) | Claude가 대화를 이해해 답하고 도구로 검색 |

`.env.example`을 `.env`로 복사해 키를 넣으면 됩니다.

> 음성 인식(마이크)은 브라우저 기능(Web Speech API)을 쓰므로 **https 주소나 localhost에서만** 동작합니다. 안드로이드 크롬, 아이폰 사파리에서 됩니다. 안 되는 기기에서는 자판의 마이크 버튼(음성 입력)을 쓰도록 안내합니다.

## 내 건강수첩

- **등록**: 건강검진 결과지 사진을 찍으면 AI가 수치를 읽어 칸을 채워 줍니다. 어르신이나 보호자가 값을 확인한 뒤에 저장합니다. 직접 입력도 됩니다(AI가 꺼져 있으면 직접 입력만 됩니다).
- **판정 표시**: 혈압, 혈당, 콜레스테롤, 간·콩팥 수치 등을 국가건강검진 기준을 단순화한 `정상 / 주의 / 확인 필요`로 보여 줍니다(`public/health-rules.js`). 진단이 아니라 의사와 상의할 항목을 고르는 용도입니다.
- **기억하고 참고하기**: 질문할 때 건강수첩 요약이 함께 전달됩니다. "어지러워요"라고 하시면 신경과를 안내하면서 "지난 검진에서 혈압 수치를 상의해 보시라고 나왔어요"라고 덧붙이는 식입니다. "내 건강검진 결과 어때?"라고 물으면 결과를 요약해 드립니다.
- **의사 선생님께 보여 드리기**: 진료실에서 화면 그대로 보여 드릴 수 있는 큰 글씨 요약(지병·약·알레르기·최근 검진)입니다.
- **저장 위치**: 건강정보는 민감정보라 **서버에 저장하지 않고 휴대폰(브라우저 저장소)에만** 둡니다. 결과지 사진도 수치를 읽은 뒤 버립니다. 사용자가 "질문할 때 참고하게 하기"를 끄면 질문에 실려 가지도 않습니다.
- **한계**: 휴대폰을 바꾸거나 인터넷 기록을 지우면 사라집니다. 정식 서비스에서는 회원 계정 + 암호화 저장 + 별도 동의를 받아 서버에 백업하고, 자녀 휴대폰과 함께 보는 기능으로 넓히는 걸 권합니다. 국민건강보험공단 검진 결과를 본인 인증으로 바로 불러오는 연동(마이데이터)도 다음 단계 후보입니다.

## 공공데이터 키 받기 (E-GEN)

말씀하신 "이젠"은 국립중앙의료원이 운영하는 **응급의료포털 E-GEN**입니다. 이 데이터는 공공데이터포털에서 무료 오픈 API로 받을 수 있습니다.

1. [data.go.kr](https://www.data.go.kr) 회원가입
2. 아래 두 API를 검색해 **활용신청** (보통 바로 또는 1~2시간 안에 승인)
   - 국립중앙의료원_전국 병·의원 찾기 서비스
   - 국립중앙의료원_전국 약국 정보 조회 서비스
3. 마이페이지의 **일반 인증키(Decoding)**를 `EGEN_SERVICE_KEY`에 넣기

연동 코드는 `server/egen.js`에 있습니다. 이 개발 환경에서는 data.go.kr에 접속할 수 없어서 **실데이터로는 아직 시험하지 못했습니다.** 키를 받은 뒤 아래를 꼭 확인하세요.

- 진료과목 코드(`QD`, `server/knowledge.js`의 `DEPARTMENTS`)가 활용가이드 코드표와 맞는지
- 상세조회 응답에 진료시간(`dutyTime1s`~`dutyTime8c`)과 진료과목(`dgidIdName`)이 오는지
- 개발계정은 하루 호출 수 제한이 있습니다. 서버에 캐시(위치 10분, 지역 목록 1시간, 기관 상세 24시간)를 넣어 두었습니다.

## 구조

```
care-guide/
├─ public/              화면 (HTML/CSS/JS, 설치형 웹앱)
│  ├─ index.html        큰 글씨·큰 버튼, 119 버튼 상시 노출
│  ├─ app.js            음성 인식, 소리로 읽기, 카드 그리기, 가족에게 공유
│  ├─ health-ui.js      내 건강수첩 화면 (등록·사진 읽기·의사에게 보여 주기)
│  ├─ health-rules.js   검진 항목·판정 기준 (서버와 같이 씀)
│  ├─ dom.js            화면 요소·저장소 도우미
│  └─ style.css
├─ server/
│  ├─ index.js          Express 서버 (/api/chat, /api/places, /api/guides/:id, /api/checkup/extract)
│  ├─ health.js         건강수첩 입력 정리, 결과지 사진 → 수치 읽기(Claude)
│  ├─ assistant.js      응급 감지 → Claude 또는 기본 안내로 답 만들기
│  ├─ ai.js             Claude 연동 (도구: search_places, get_document_guide)
│  ├─ egen.js           국립중앙의료원 API 연동 + 거리 계산 + 캐시
│  ├─ hours.js          "지금 문 열었나" 계산 (밤샘 영업·공휴일 포함)
│  ├─ knowledge.js      진료과 코드, 증상→진료과 규칙, 응급 신호, 서류 안내
│  └─ mock-data.js      키 없을 때 쓰는 예시 기관
└─ test/              core.test.js, health.test.js
```

## 안전장치

- **응급 신호 우선**: "가슴이 조여요", "한쪽 팔에 힘이 없어요", "말이 어눌해요" 같은 말이 들어오면 AI 답을 기다리기 전에 서버가 먼저 감지해 119 카드를 맨 위에 띄웁니다.
- **진단하지 않음**: 시스템 프롬프트에서 병명 단정·약 용량 안내를 막고, 방문 전 전화 확인을 안내합니다.
- **서류 안내는 고정 문구**: 보험·병원 서류는 AI가 지어내지 않도록 `knowledge.js`의 검수된 내용을 도구로 불러와 씁니다. 보험사마다 기준이 다르므로 문구에 확인 안내를 넣었습니다. 출시 전에 손해사정사·원무과 실무자 검수를 받으세요.

## AI 설정

- 모델: `claude-opus-5-5` (`CARE_AI_MODEL`로 변경 가능)
- 응답 속도를 위해 effort는 `low` (`CARE_AI_EFFORT`). 답이 부족하면 `medium`으로 올려 보세요.
- 정책상 답을 거절하는 경우를 대비해 서버 측 대체 모델(`fallbacks: "default"`)을 켜 두었습니다. 그래도 거절되면 119·병원 전화 안내로 답합니다.
- AI 호출이 실패하면 자동으로 기본 안내로 바뀌어, 어르신이 빈 화면을 보지 않게 했습니다.

## 다음 단계 제안

1. **실데이터 검증**: E-GEN 키로 서울·지방 몇 곳을 실제 조회해 진료시간·진료과 필터 정확도 확인
2. **앱 출시**: 지금 구조 그대로 Capacitor로 감싸 안드로이드/iOS 앱으로 낼 수 있습니다. 음성 인식은 네이티브 STT로 바꾸면 사투리·작은 목소리 인식률이 좋아집니다.
3. **보호자 연결**: 자녀 휴대폰과 연결해 "어머니가 지금 ○○병원을 찾으셨어요" 알림, 병원 예약 대행
4. **추가 데이터**: 건강보험심사평가원 병원정보서비스(전문의 수·장비), 응급실 실시간 병상(E-GEN 응급의료기관 정보), 휴일지킴이약국
5. **규제 확인**: 의료법상 의료 광고·환자 유인 금지(병원 제휴 수익모델 설계 시), 건강정보는 민감정보이므로 개인정보 처리방침과 별도 동의, 앱이 '진단'이 아니라 '안내'로 보이게 하는 문구
